# V1 停止机制及预算假设核查

此前将 step_limit 解释为阶段步数上限不准确。本轮逐步重放 300 组运行，所有候选规格和停止条件均与日志一致，未发现阶段总步数限制。

run_p1.py 在拒绝后对对应推进因子开平方。F/# 因子从 0.707 出发，超过 0.99 停止；视场因子从 1.414 出发，低于 1.01 停止。第六次累计拒绝后分别变为 0.994597076、1.005427529，触发 step_limit。成功步骤不会重置该因子，因此六次拒绝不必连续。

这与单次 DLS 请求的 50 循环是两个独立机制。日志缺少每次迭代的 merit 轨迹和实际完成循环数，无法仅据 step_limit 证明 DLS 预算不足，也不能证明物理不可实现。

建议首轮处方：[52, 5, 11]。第一套是全失败处方中最接近共同规格目标的样本，其余为 Rule 2/3 规格不一致的确定性选样。三条规则均应运行并设置同环境 50 循环控制。

未启动 OpticStudio 会话，仅读取本地 API 枚举：固定模式只支持 1、5、10、50 循环，没有 Fixed_100_Cycles 或 Fixed_200_Cycles。若做额外预算对照，应明确比较每个候选 1、2、4 次各 50 循环的 DLS 调用；调用间保留当前候选和优化结果，完成全部调用后再执行原有验收与推进。这包含 DLS 重新调用影响，不能称作单次固定 100/200 循环。
