# 辅助线程限制与 Ray 8 并行验收

## 单组数值回归

Case 2 / Rule 2 使用同一初始处方，分别重新执行未限制版和辅助线程限制版。两组均为 21 次尝试、请求 1050 个 DLS 循环。两组相对 P1 V1 的全部比较指标差值为零，步骤与停止原因一致。

| 指标 | 对照版 | 限制版 |
|---|---:|---:|
| 子进程总耗时 s | 240.13 | 150.75 |
| DLS 总耗时 s | 215.96 | 141.15 |

计时为单次实测，包含机器当时负载差异，不能据此宣称稳定加速比。模型资源限制在 NumPy 导入前设置，OpticStudio 继续使用 2 核。

## 完整 9 组并行测试

- 总耗时 344.94 秒，实际并发峰值 8。
- 最低可用物理内存 1.014 GiB。
- 系统提交峰值 23.221 GiB，峰值提交比例 75.82%。
- 全程系统 CPU 均值 34.79%，峰值 68.90%。
- 8 组同时运行时系统 CPU 均值 45.81%。
- 9 组均正常退出；停止事件为零；全部终点、MTF、RMS、共轭残差比较差值为零。
- 共请求 7450 个 DLS 循环，与 V1 一致。API 未提供实际完成循环计数。

## 运行时审计

- 9 份模型审计均确认 NumPy 在限制设置后导入，模型导入后 4 个线程，私有提交约 21.6 MiB。
- 全部 Ray 调度 worker 均未加载 run_p1、p1_engine、CLR、ZOSAPI；本次也未加载 NumPy。
- 关闭 worker 预启动，保留 CPU=16 和任务 CPU=2，设置 worker soft limit=8。
- 实际执行任务使用 8 个独立 Ray worker。原始 PID 采样中最多 18 个 worker 相关 Python 条目，包含 Windows 启动器与短暂预取 worker，故不将原始 PID 数直接等同于任务数。
- 133 个历史文件逐一校验通过，V1 光学流程未变。
- 资源配置适用于本次版本和已测 P1 范围；后续批量继续启用物理内存与提交保护。

详细逐组差异见 acceptance.json，资源时间序列见 telemetry.jsonl，已验证运行配置见 validated_runtime_profile.json。
